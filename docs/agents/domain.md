# Domain docs

This is a single-context repository. Domain vocabulary belongs in root `CONTEXT.md`; architecture decisions belong in `docs/adr/`. These files do not exist yet and should be created only when terms or decisions need recording.

Before exploring a relevant area, read `CONTEXT.md` and applicable ADRs if present. If absent, continue without creating placeholders.

Use the terminology in `CONTEXT.md` for issue titles, proposals, hypotheses, and test names. If a term is missing, check whether it is a real domain gap before adding it. Surface conflicts with an existing ADR rather than silently overriding it.
